# antiGen

Welcome to antiGen, a model that learns amino acid substitution probabilities for viral proteins based on phylogenetic trees. This repository is intended for (1) training antiGen on phylogenetic data, (2) querying substitution probabilties predicted by antiGen, and (3) running the evaluations reported in the antiGen manuscript.

## Install

```bash
pip install -e .                 # core: from-scratch transformer + BLOSUM62 / PSSM / gated (no model downloads)
pip install -e ".[esm]"          # + ESM-2 pretrained language model
pip install -e ".[dca]"          # + EVcouplings (needs external `plmc`)
```

antiGen requires Python version ≥ 3.10. The above commands install the CLIs `antiGen-train`, `antiGen-infer`, `antiGen-eval`, and
`antiGen-validate-examples`, and the importable package `import antiGen` (works from any directory).

## Quickstart (train → infer, ~1 minute on CPU)

Uses the tiny bundled toy dataset in `data/toy/` — no external data or downloads.

```bash
# 1. (optional) sanity-check the training-data file
antiGen-validate-examples data/toy/examples_cutoff_toy.txt --variant toy

# 2. train a small from-scratch transformer
antiGen-train --model-type transformer --examples data/toy/examples_cutoff_toy.txt \
    --d-model 32 --num-layers 1 --epochs 3 --batch-size 4 --output-dir ./checkpoints

# 3. score substitutions for the query sequences in a FASTA
antiGen-infer ./checkpoints/fitness_*.pt data/toy/query.fasta -o scores.csv
```

# 1. Training antiGen

## Training data (generated by `antiGen-data`)

antiGen training data is produced by the companion **`antiGen-data`** tool — a C++/CUDA
application that grows a mutation-annotated phylogeny by parsimonious attachment and emits,
per train/test cutoff, the training examples plus position-specific scoring matrices (PSSMs).
It is a **separate repository**. Each cutoff directory it writes contains:

```
output_<dataset>/
  examples_cutoff_<value>.txt     # training/testing examples (one record per ancestral sequence)
  pssms/root.csv                  # root PSSM (the pssm_root / PSSM-model source)
  pssms/<variant>/time_*.csv      # per-variant PSSMs over time (variant-emergence eval)
```

An `examples_cutoff_*.txt` record holds a sequence, its `TRAINING`/`TESTING` split, variant-root /
descent flags, and the substitutions observed in that sequence's children (the training target).
`antiGen-validate-examples <file> [--variant V]` checks a file is well-formed (single consistent
sequence length, alphabet `ACDEFGHIKLMNPQRSTVWY*-`, in-range positions, ≥1 training example). The
bundled `data/toy/examples_cutoff_toy.txt` is a hand-built miniature in the same format for the
quickstart.

**Pointing antiGen at data.** Give an explicit file with `--examples <path>` (works for any
dataset with no code edits), or use a built-in dataset shortcut which resolves
`examples_cutoff_<cutoff>.txt` under `$FITNESS_DATA_ROOT` (or an explicit `--data-dir`):

| Flag | Dataset | Variant | `--cutoff` | Eval region |
|------|---------|---------|------------|-------------|
| *(default)* | SARS-CoV-2 spike | BA.2 (or `--variant`) | 1, 4, or 5 | RBD (330–530) |
| `--flu` | Influenza HA | J or K | 12 | full sequence |
| `--rsv-a` | RSV-A F | A.D.1.6 | 74 | full sequence |
| `--denv2` | Dengue 2 envelope | 2II_F.1.1.2_annotated | 191 | full sequence |

```bash
export FITNESS_DATA_ROOT=/path/to/antiGen-data      # holds output1/, output_flu_full_cutoff12/, ...
antiGen-train --flu --cutoff 12 --model-type transformer --output-dir ./checkpoints
```

## Model architectures (`--model-type`)

| Model | `--model-type` | Extra install | Description |
|-------|----------------|---------------|-------------|
| Transformer | `transformer` | — (core) | Small transformer trained from scratch. **Default; no downloads.** |
| ESM-2 | `esm2` | `.[esm]` | ESM-2 protein LM (default `esm2_t12_35M_UR50D`), frozen/partial/full finetune |
| BLOSUM62 | `blosum62` | — (core) | Static BLOSUM62 substitution matrix (no training, eval only) |
| PSSM | `pssm` | — (core) | Per-position `log(count+1)` from the root PSSM (no training, eval only) |
| Gated | `gated` | — (core) | Learnable per-position blend of two predictors (`--gate-partner-a/-b`, `--gate-variant`) |
| EVcouplings | `evcouplings` | `.[dca]` + `plmc` | Mean-field DCA Potts model fitted from a pandemic MSA (eval only) |
| EVE | `eve` | — (core) | EVE VAE (frozen or finetuned) trained on a pandemic MSA |
| Tranception | `tranception` | — (core) | Tranception autoregressive scorer (frozen or finetuned) |

For the pretrained ESM-2 backbone, three finetuning strategies: **frozen**
(`--freeze-backbone`, head only), **partial** (`--freeze-backbone --finetune-layers N`), and
**full** (no freeze flags). MSA models (`evcouplings`/`eve`/`tranception`) additionally need
`--msa` / `--metadata`; their date cutoff is derived from the dataset MRCA + `--cutoff` (or
`--date-cutoff`).

```bash
# from-scratch transformer (the default)
antiGen-train --model-type transformer --d-model 128 --num-layers 2 \
    --epochs 64 --batch-size 64 --lr 1e-4 --flu --output-dir ./checkpoints

# ESM-2, partial finetune of the last 4 layers
antiGen-train --model-type esm2 --freeze-backbone --finetune-layers 4 --lr 1e-4 --flu

# gated blend of a from-scratch transformer and the root PSSM
antiGen-train --model-type gated --gate-partner-a fitness_predictor --gate-partner-b pssm \
    --gate-variant static --flu
```

Checkpoints are written to `--output-dir` as `fitness_<run_prefix>.pt`, alongside a
`manifest.json` recording the full recipe. They are self-describing (they store the complete
`ModelConfig`), so `antiGen-infer` / `antiGen-eval` reload them standalone.

# 2. Querying substitution probabilities

`antiGen-infer <checkpoint> <queries.fasta>` runs a forward pass on one or more query sequences
and writes the model's probability distribution over substitutions relative to each query.

```bash
antiGen-infer ./checkpoints/fitness_*.pt my_queries.fasta -o scores.csv
```

Default **long** output — one row per candidate substitution:

```
query_id,position,ref_aa,alt_aa,prob
toy_root,0,M,A,0.00148030
toy_root,0,M,C,0.00164760
...
```

`prob` is the inferred probability of each possible amino acid substitution relative to the
query (including premature stop codons `*` and gaps `-`, i.e. point indels). It comes from a
single **whole-sequence softmax** over the (position × amino-acid) map with the wild-type cell
removed — the same quantity the model is trained on (a distribution over mutation *events*, not
independent per-position categoricals). Per query the probabilities sum to 1. Use `--format wide`
for a position × amino-acid matrix, and `--drop-gap-stop` to exclude the `-`/`*` columns.

**Length / alignment.** The from-scratch transformer (and EVE / Tranception / EVcouplings / PSSM)
predict on a **fixed, aligned coordinate frame**: query sequences must match the training
reference length and alignment. ESM-2 / BLOSUM62 accept any length. `antiGen-infer`
errors clearly if a query's length is incompatible.

# 3. Running the manuscript evaluations

`antiGen-eval` scans a directory of checkpoints, groups them by model, and writes unified
per-variant comparison CSVs against a set of fixed baselines.

```bash
antiGen-eval --dataset sc2 --data-dir $FITNESS_DATA_ROOT/output1 \
    --checkpoint-dir ./checkpoints --output-dir ./evals_sc2
```

It produces two metric families per variant: **quantile hit-rate** (how often observed mutations
fall in the model's top-q% predictions) and **variant-emergence** (across top-q quantiles
q = 0.1 … 0.9). These are termed next-mutation recall and PSSM precision in the paper, respectively. Baselines come from `data/baselines*/` plus two built from the root PSSM
(`pssm_root` and the position-only `pssm_root_position`). Ties at a top-q boundary are broken
**fractionally** (the expected value under random tie-breaking) so coarse-valued predictors like
BLOSUM62 are scored fairly and deterministically. `--emergence-only` cheaply recomputes just the
variant-emergence CSVs (one forward pass per model, no test-set sweep).

**Deep mutational scanning (DMS).** Score a checkpoint against ProteinGym substitution data:

```bash
python -m antiGen.dms.parse_dms --source_dir /path/to/ProteinGym/substitutions --target_dir ./antiGen/dms/data/dms_spike
python -m antiGen.dms.evaluate_dms --checkpoint checkpoints/model.pt --dms_dir ./antiGen/dms/data/dms_spike
```

The SLURM scripts used for the manuscript runs are in [`examples/slurm/`](examples/slurm/); they
embed lab-specific paths/partitions and are meant to be copied and edited for your environment.
